# 03-美術規範與已知失敗模式

這份是**每一張圖都適用**的硬規範，與各款遊戲的畫風設定分開。畫風寫「這款遊戲長什麼樣」，這份寫「不管哪款遊戲都不能違反的事」。

圖交出來之後，本機的 `tools/qa.ps1` 會逐張量測並標成 pass / warn / fail：**fail 的必須重生**（燒生圖額度），warn 只印在驗收總覽圖上給人眼判斷。一款遊戲的素材是三、四十張起跳（遊戲7 最後做了 45 張，分七批），一天的生圖配額做不完，所以每一條規則都是為了讓一次過關率盡量高。實戰參考：遊戲7 第一輪（第一批＋第二批）生了 14 次圖、拿到 11 張成品，其中 2 張重生——一張是模型自己加了背光圈與雲朵，一張是白底白物去背失敗。

---

## 一、通用美術規範（12 條）

1. **背景照第二節的規則決定**，不要自己選。背景畫錯整張圖報廢，因為去背在本機做，分不開就救不回來。
2. **畫面只有一個主體**：不要第二個角色、不要額外的地面或台座、不要場景或背景物件。每張圖在遊戲裡是一個獨立可移動的 sprite，多出來的東西會跟著它一起飛。（如果我要的主體**本身就是**台座、石階、煙塵或星光，我會在該則訊息裡寫清楚——這條要擋的是「我沒點名、你自己加上去」的東西。）
3. **一則訊息＝一張圖＝一個主體**，不要把多個動作拼成一張 sprite sheet。程式是一張圖載一個貼圖（`imgTex(檔名)`），拼版的沒辦法拆。
4. **圖上不要有任何文字、數字、字母、標籤、簽名、浮水印、邊框**，除非我在該則訊息裡明確指定要寫什麼字（例外只有一種：廟宇匾額那張，我會直接寫出要刻哪三個字）。沒指定卻自己加字的，縮小後只是雜訊，而且改不掉。
5. **不要投影陰影、不要發光光暈、不要光線特效、不要動態模糊、不要粒子或飄浮碎屑。** 這些在遊戲裡是即時算的（角色會動、光會變），畫死在圖上會跟場景打架；投影還會被去背的邊緣 flood fill 卡住，在主體旁邊留下一塊灰。
6. **主體完整入鏡，四邊都要留白，任何一處都不可以被畫布邊緣切到。** 本機會依內容邊界裁切，被切掉的邊緣補不回來，只能重生（「主體被畫布切到」是自動驗收裡少數幾條 fail 級的其中一條）。
7. **主體置中**，站姿角色腳底靠近畫面下方。不用追求精確（精確也做不到，見第四節）；這條要避免的只是嚴重偏到一角。
8. **朝向依引擎決定**（Claude 會在階段 0 告訴你是哪一種，見 02）：
   - **2D 橫向捲軸**：角色一律**面向畫面右邊**（預設往右走，往左時由程式水平翻轉）。
   - **3D 立牌場景**：**正面平視是硬性要求**——立牌永遠面向鏡頭，3/4 斜角的圖擺進場景會站歪。站在鏡頭前模仿玩家的主角畫**正面朝鏡頭**，載具與側身移動的角色才畫**車頭／面朝右**。

   不管哪一種，**同一組影格的朝向必須一致**，否則動畫播起來會前後亂轉。
9. **表情要好笑、誇張、討喜**，不可以可憐、兇惡或恐怖。玩家是四歲的小玩家，這系列遊戲刻意沒有 Game Over，連失敗動畫都要讓他笑出來、想再故意撞一次。
10. **不要模仿任何現有卡通、遊戲、動畫或品牌的角色造型。** 遊戲會發佈在公開網站，美術必須原創。
11. **同一個角色的不同動作、不同張，配色、比例、服裝配件必須完全一致。** 那些張是連續播放的影格，配色差一點在動畫裡就是閃爍。
12. **細節不要過碎。** 這些圖在電視上很小——遊戲7 實測，最大的媽祖神像在螢幕上約 265 像素、燈籠只有約 92 像素——靠的是高對比剪影和簡化造型，碎細節縮小後只會變成雜訊。

補充兩條情境規則：

- **會被程式隨機染色的物件，本身要畫成中性的淺灰白色。** Three.js 的 sprite 材質色會拿去乘貼圖，程式就是這樣換色的（遊戲7 的柱子與台基每一局從 5 組配色隨機抽一組；煙塵那張也是同一張圖靠程式上棕色或灰色）。主體本身有顏色就染不上去。這類主體一定要搭第二節的洋紅底。
- **一批之內不要切換畫風。** 畫風以該款遊戲的畫風句為準，同一批圖會並排出現在同一個畫面上。

## 二、背景怎麼畫（去背友善規則，最重要的一節）

**實測：指令白紙黑字寫「背景全透明」，遊戲7 第一輪 11 張成品裡只有 1 張真的是透明背景**——其餘 3 張是棋盤格假透明、7 張是純色不透明底。

所以本機一律做三路分流去背（真 alpha／棋盤格／純色底），三種都收。**你要保證的不是「透明」，是「背景跟主體分得開」。**

判斷規則只有兩條：

- **主體是深色或高彩度** → 照常要求「背景全透明（PNG alpha），不要棋盤格、不要白底、不要任何底色、不要邊框」。就算交出棋盤格或米色底，本機也分得開（遊戲7 的兩尊神將就是交米色底，照樣救得回來）。
- **主體含大面積白色、米白、淺灰、淺黃** → **改成要求鮮豔洋紅色純色底**，寫法：
  > 這一張背景請填滿鮮豔的洋紅色純色底（不要透明、不要白色、不要漸層），方便後製去背。

  為什麼是洋紅：洋紅的綠通道接近 0、白色是 255，差距最大，去背容差（`build.ps1` 的 `純色容差`，預設 26、洋紅底這幾張開到 60）都不會誤傷主體；白對白則是任何容差都分不開。
  不這樣做的實測代價：白雲畫在白底上，第一版被去背整個吃光；廟宇的淺灰白石造台基同樣只剩幾條線。兩張都重生，兩次額度。

另外三點，兩種背景都適用：

- 用洋紅底時，**主體上不要出現粉紅、洋紅、紫紅色**，會連主體一起被挖掉（自動驗收有一條專門在抓「主體裡混到洋紅」）。
- **背景不要漸層、不要暈影、不要邊框、不要在背景上打陰影。** 去背靠的是從四邊往內 flood fill，一圈不均勻的顏色會讓它停在半路，留下一圈色塊。
- 背景是純色時**要填滿整個畫布**，不要留一圈別的顏色或一條白邊。

## 三、已知失敗模式（實際發生過，不要重蹈）

| # | 失敗模式 | 實際案例 | 對策 |
|---|---|---|---|
| 1 | **把識別碼、色碼當成要畫的標籤畫進圖裡** | prompt 開頭寫素材編號（`CHAR004` 這種）、顏色寫成 hex（`#F1700C`），模型把字串畫在圖上 | prompt 一律不出現 ID 和 hex 色碼；顏色用「亮橘色」「奶油色」這種文字描述。編號對應完全在本機處理（送出順序＝下載順序） |
| 2 | **自己加沒有要求的裝飾** | 媽祖神像那張，模型自己加了背光圈和一圈雲朵，整張報廢重生 | 沒寫的東西就不要加。特別是光圈、光暈、雲、星星、地面、台座、裝飾邊框 |
| 3 | **模型照「常識」補了我不要的結構** | 神龕背板第一版直接畫成一扇大門——但神像是站在這片牆前面的，變成「神明坐在門口」 | 不要的結構要在 prompt 裡寫死排除（該張現在寫著「絕對不要有門、門板、門環或門釘」） |
| 4 | **同一批連續生到第 5~8 張之後上下文飄移，開始畫錯東西** | 連續生了五張工程車之後，第六張要「一顆破壞用的鐵球」，結果**又畫了一台水泥車** | 一批控制在 6~8 張；若某一張的主體跟前面幾張差很多，**該張 prompt 開頭先寫排除句**，例如「這一張不要畫任何車輛」。重生時也要加這句才拉得回來 |
| 5 | **左右鏡像畫反** | 五張工程車裡有一台**駕駛艙生在右邊、吊臂朝左上**，其他四台都是駕駛艙在左 | **不要為了鏡像重生**，本機在 `assets.json` 加一個「水平翻轉」就解決，省一次額度。生圖時仍要在 prompt 寫死朝向（「車頭朝右」） |
| 6 | **白底白物去背失敗** | 白雲、淺灰白石造台基（見第二節） | 淺色主體一律洋紅底 |
| 7 | **主體被畫布邊緣切到** | 舉高的手、伸長的吊臂最常被切 | 動作誇張時要主動把主體縮小一點，寧可四邊留白多一些。這是 fail 級，一定重生 |
| 8 | **回一堆文字說明才生圖，或先問我要不要調整** | — | 直接生成圖片就好，不需要文字說明，不需要先確認，也不需要回覆任何代號或哨兵字串 |

還有一個不是模型的錯、但你要知道的前提：**繪圖工具一定會改寫 prompt**，這是產品內建行為，擋不掉。所以描述要寫成「就算被改寫一次也還原得回來」的具體造型敘述，不要依賴精確措辭。

## 四、為什麼這份文件不寫幾何規格

審查階段量過遊戲8 已上線的 32 張素材，條件是「有附參考圖、同一個 Project、指令寫得很細」：

| 量到的事 | 實測落差 |
|---|---|
| 同角色不同影格「高度佔畫布比例」 | **19.8 個百分點** |
| 水平中心飄移 | **8.5 個百分點** |
| 底部基準線落差 | **16.6%** |

在最有利的條件下都是這個數字，所以「主體高度要佔畫布百分之幾」「水平置中誤差幾 %」「腳底壓在幾 % 的位置」這類數值要求**服從率接近 0，寫了只會稀釋真正有效的指令**，一律不寫。

畫布尺寸同理不寫：網頁版沒有尺寸參數。遊戲8 現役素材的原圖尺寸從 1254×1254、1536×1024，到 1297×1212、1205×1305、1672×941、2048×768 都出現過，品質完全合格——把尺寸當硬性條件只會把好圖丟掉。

**後段實際上是這樣收尾的**（誠實版，不要以為本機會自動把幾何修好）：

- `build.ps1` 做的是：去背三路分流 → 邊緣羽化 → 依內容邊界裁切或整張縮放到指定寬度 → 需要時水平翻轉 → 壓成 WebP（實測省 88~92%：遊戲7 第一批 7 張，同內容 PNG 4.87MB → WebP 400KB）。
  **它沒有「統一尺度／統一水平中心／統一底部基準線」的功能**，也不會讀素材清單的 `組` 欄位。
- `qa.ps1` 會量測並疊出「洋蔥皮」圖，讓人眼一次看出同組影格的尺度／中心／底線有沒有飄。
- **真正把幾何補起來的是遊戲程式**：Claude 逐張把實際輸出的長寬比寫進程式，再逐張給一個世界高度——
  挑法是讓「角色本人」看起來一樣大，**不是讓圖一樣高**（因為舉高的手、鏟子、水泥桶這些延伸物會讓圖高差很多，遊戲7 小師傅四張同寬 400px 之後圖高是 995／679／1020／626，差 1.63 倍，那是取景差異不是畫錯）。

**所以你的力氣要花在**：造型設計、配色、朝向、表情、同一組影格的一致性、背景選對。這幾件事程式做不到，只有你能做。

而幾何這一段，你**做得到的替代要求**只有一個（質性、不給數字）：
> 同一組影格裡，**讓主體在畫面裡佔的份量盡量接近**，不要有的畫得很大、有的縮很小。

## 四之二、prompt 裡唯一允許出現的識別碼

這條在別份文件裡曾經前後不一，**以這裡為準**：

| | 可不可以出現在 prompt 裡 | 為什麼 |
|---|---|---|
| **設定圖檔名**（`REF001.png`） | ✅ **允許，而且必須寫** | 那是引用設定圖的唯一指路方式，沒有它機制就不成立 |
| 素材 ID（`CH003`、`CHAR004`） | ❌ 禁止 | 實測會被當成要畫的標籤畫進圖裡。ID 對應在本機用「送出順序＝下載順序」處理 |
| hex 色碼（`#F1700C`） | ❌ 禁止 | 同上。顏色一律用「亮橘色」「奶油色」這種文字描述 |
| 批號、張數、任何編號 | ❌ 禁止 | 同上 |

> 正因為 prompt 裡會出現檔名，「圖上不可有任何文字數字」那條**不能放寬**，
> 而且落地時要用眼睛確認檔名沒被畫上去。

## 四之三、自動驗收會擋什麼（fail 級清單）

`tools/qa.ps1` 逐張量測後標成 pass / warn / fail。**fail 要重生（燒額度），warn 只印在驗收總覽圖上給人眼判斷。**
目前的 fail 級檢查有八種：

| 檢查 | 意思 | 你能不能避免 |
|---|---|---|
| `EMPTY_IMAGE` | 空圖 | ✅ |
| `NO_ALPHA` | 去背整個失敗，全圖不透明 | ✅ 照第二節選對背景 |
| `EDGE_CLIPPED` | 主體被畫布邊緣切到 | ✅ 四邊多留白 |
| `FRAG_AT_EDGE` | 邊緣有碎片殘留 | ✅ 背景乾淨、不要漸層暈影 |
| `TILE_EDGE_SOFT` | 地面拼接圖的左右邊緣不夠實 | ✅ 橫幅要填滿、邊緣不要淡出 |
| `SHEET_GUTTER_MISSING` | 多格圖沒有分隔帶 | ✅ 本來就不該交多格圖 |
| `PALETTE_DRIFT` | 招牌色沒出現 | ❌ **不用理會**——目前招牌色寫死成某一款遊戲的配色，換款就不適用，由 Claude 每款自行調整 |
| `FRAME_SCALE_DRIFT` | 同組影格大小差太多 | ⚠️ 見下 |

**`FRAME_SCALE_DRIFT` 要誠實講清楚：** 它是 fail 級，也就是「第四節叫你別管的幾何，驗收其實會擋」。
但它目前只對某幾組寫死的 ID 生效，多數遊戲根本不會觸發。
你唯一該做的是第四節末尾那條質性要求——**同一組影格讓主體佔的份量接近**——其餘交給 Claude。
不要為了它去寫百分比數字，那反而會稀釋有效指令。

## 五、一致性怎麼做（比寫規則有效）

- **同一個角色的多張影格，要在同一個對話裡連續生。** 實測小師傅四格（站立待機／蹲下挖地基／雙手高舉倒水泥／慶祝歡呼）連續生，臉、安全帽、背心、褲子完全一致，一次過關零重生。**這是目前維持角色一致性最有效的手段。**
- **玩法必需的物件一律在 prompt 裡寫死；只有純裝飾才留白給模型發揮。**
  遊戲7 有過一次好運：小師傅四格的 prompt 沒提工具，模型自己補上鏟子和水泥桶，剛好對上「挖地基」「倒水泥」兩關。
  **但那是運氣，不是機制**——而且「缺了玩法必需的道具」不對應任何一條自動檢查，會一路綠燈通過驗收接進遊戲，直到在電視上實玩才發現。
  所以規則是：這一關要用到的道具（鏟子、水管、掃把、球）**寫進 prompt**；至於袖口的皺褶、鞋帶的顏色這種純裝飾，交給模型發揮沒關係。
  （這與第三節第 2 條不衝突：可以補「這個動作自然會有的細節」，不可以補光圈、雲朵、星星這類我沒點名的裝飾。）
- 一批超過 6~8 張就換新對話重開一批，跨批的不一致交給本機後處理和人眼挑。

## 六、精簡版（可直接貼進 Project instructions 欄位）

Project instructions 欄位要短，長版留在 Sources。下面這段整段貼進去，每款遊戲只改【畫風】和【角色】兩行：

```
你是這個專案的美術。我每則訊息會描述一張遊戲素材，你直接生成圖片，不需要文字說明。

【畫風】<該款遊戲的畫風句>
【角色】<主角設定>

每一張都必須遵守：
1. 背景：預設全透明（PNG alpha），不要棋盤格、不要底色、不要邊框、不要漸層。
   但主體含大面積白色/米白/淺灰時，改成填滿鮮豔洋紅色純色底（我會在該則訊息裡註明），方便我後製去背；
   用洋紅底時主體上不要出現粉紅、洋紅、紫紅色。
2. 畫面只有一個主體，不要第二個角色、不要多加地面或台座、不要場景。一則訊息只生一張圖，不要拼成 sprite sheet。
3. 圖上不要有任何文字、數字、字母、標籤、簽名、浮水印、邊框——除非我在該則訊息裡明確指定要寫哪幾個字。
```
