# 05 設定圖流程（角色與場景）

> 一句話：**先生一張設定圖存進本專案的 Sources，之後每一張相關素材都引用它。**
> 角色與場景都適用。

---

## 0. 這套流程為什麼成立（2026-08-20 在真實頁面上實測）

三件事都測過，不是推測：

1. **Sources 裡的圖，後續新對話真的看得到畫面內容。**
   測法是不花生圖額度的文字探針——請模型描述 Sources 裡的一張角色圖，並要求「看不到就老實說」。
   它答出：黃色安全帽上有紅色圓徽與「廟」字、兩側青綠雲紋、白色短袖 T、藍色吊帶牛仔褲、紅領巾、
   黃橘工作靴配紅鞋帶與深咖啡鞋頭、約三頭身、腰間工具帶掛鐵鎚、背後斜插捲筒圖紙。
   **細節密度不可能是從檔名猜出來的。**

2. **引用它生新姿勢有效。** 同一個新對話接著要「跳起來歡呼」，交出來的圖：
   安全帽（含紅圓徽與「廟」字、綠雲紋）、紅領巾、白 T、藍吊帶褲、胸前金色圖案、
   黃橘工作靴＋紅鞋帶＋深色鞋頭、黃黑手套、工具帶＋鐵鎚、背後捲筒、三頭身比例——**全部正確**，姿勢也對。

3. **但同一次測試裡，「面向右邊」沒服從（畫成正面偏左）、「背景全透明」沒服從（白底）。**

所以這套機制的定位要記牢（第 6 節會再講一次）：
**它解決「設計一致性」，不解決「指令服從度」，也不解決「幾何一致性」。**

另外：**Sources 是會被自動檢索的**（不指名檔名問「素材規劃第一批有哪些 ID」，它答對而且標了引用來源）。
但那是「明顯在問資料」的訊息；**生圖訊息不保證觸發檢索**，所以引用設定圖時**一定要把檔名寫進 prompt**，不要指望它自己去翻。

---

## 1. 什麼時候要做設定圖

只要符合任何一項就做：

| 情況 | 做哪一種 |
|---|---|
| 同一個角色要生多個姿勢或動畫影格 | 角色設定圖 |
| 一款遊戲有兩個以上角色 | 每個角色各一張 |
| 同一個場景要拆成多層（遠山／中景／地面／前景）分開生 | 場景設定圖 |
| 同一個場景要出多個時段或狀態（白天／黃昏／下雨） | 場景設定圖 |

只出現一次、之後不會再有第二張的小物件（一顆石頭、一朵煙）**不需要**設定圖。

---

## 2. 角色設定圖

### 要畫什麼

一張圖裡放**同一個角色**的數個視角與表情：

- 正面站姿（主圖，最大）
- 側面站姿
- 2~3 個表情特寫（開心／驚訝／得意）

配色與配件要清楚可辨——這張是之後十幾張的母本，看不清楚的地方後面每一張都會各自亂猜。

### 三件必須註明的事

1. **這張是設定圖，背景給白色或淺灰即可**，不需要透明、不需要洋紅底（它不會被去背）。
2. **不要有文字、編號、標籤、箭頭、尺規線**。設定表常見的那些標註一律不要。
3. **這張不是遊戲素材**：它不會進後製、不會被縮圖、不會被程式載入。

### 不滿意就重生，不要將就

這一張是之後十幾張的母本，錯誤會被複製十幾次。**重生一張設定圖，比之後重生十幾張素材便宜太多。**

---

## 3. 場景設定圖

### 要畫什麼

該場景的**全景基準圖**——一張完整構圖，看得出來：

- **分層關係**：由遠到近有哪幾層，各層的相對位置
- **整體色調**：主色與配色
- **光線方向**：太陽在哪邊、影子往哪倒
- **遠中近景的色彩層次**：越遠越淡、越遠越偏冷（空氣感）

它是一張**完整場景**，不是去背素材，所以第 2 節那些「單一主體、背景透明」的規則在這一張**不適用**。

### 它解決什麼

**色彩與光線的一致性。** 一個場景如果拆成遠山、中景、地面、前景四張分別生，各自的色溫與明度會對不起來——
遠山偏暖、地面偏冷，疊起來就像四張不同遊戲的圖拼在一起。有一張基準圖可以指，這個問題就消失了。

### 怎麼引用

> 參考 Sources 裡 REF101.png 的整體色調與光線方向，這一張畫**該場景的遠山那一層**：
> 整張填滿畫面、不要留白、左右邊緣要能無縫接續，畫面上不要有任何角色或前景物件。

同一個場景的不同時段也一樣：

> 參考 REF101.png 的構圖與分層，這一張畫**同一個場景的黃昏版**：構圖完全一樣，只改光線與色溫。

## 4. 命名

| 用途 | 編號段 |
|---|---|
| 角色設定圖 | `REF001`、`REF002`… |
| 場景設定圖 | `REF101`、`REF102`… |

**一定要用 `REF` 前綴，不可以用 `CH` 或 `BG`。**
理由：`CH001` 在遊戲7 的素材清單裡已經是主角的站立影格，`BG001` 已經是背景圖，會撞號。
（2026-08-20 那次實測上傳的檔名確實是 `CH001.png`——那正是這條規則要避免的情況。）

**編號一旦定下就不改名。** 一是所有 prompt 都靠這個檔名指路；二是 Sources 的每一列只有「下載」和「刪除」兩個動作，
**不能改名、也不能編輯內容**。要換版本只能刪掉舊的重傳。

---

## 5. 引用模板（每一張都照這個寫）

四段缺一不可：

```
完全沿用 Sources 裡 REF001.png 的那個角色：配色、服裝、配件、頭身比例一模一樣，
不要改造型、不要換衣服、不要加新的配件。
這一張畫：<這張要的動作或表情>。<朝向：面向右邊／正面平視朝向鏡頭>。
只畫一個姿勢、單一主體。不要畫成多格設定表、不要有分格線、不要在旁邊附上其他視角或表情小圖。
圖上不要有任何文字、數字或編號。
```

配套規則：

- **玩法必需的道具要寫進 `<這張要的動作>` 裡**，不要留給模型猜（理由見 03 第五節）。
- **朝向每張都要寫**，但**生反了不要重生**——本機加一個「水平翻轉」就解決，省一次額度。
- **第三段每一張都要寫**，見下一節。

---

## 6. 陷阱：模型很可能連版面一起抄

設定圖本身就是「多視角＋多表情」的版面。模型抄的不只是角色，**很可能連版面一起抄**，
交出一張新的設定表，而不是你要的那個單一姿勢。

- 模板的**第三段每一張都要寫**，不能因為前一張正常就省略。
- 真的交出多格圖時，重生的 prompt **在句首先明講**：
  > 上一張畫成多格設定表了，這一次只畫一個姿勢、一個主體。

  理由：同一個對話的上下文會把模型帶回去重複上一次的錯，不主動切斷就會再錯一次。
  （同樣手法驗證過：遊戲7 連續生了五張工程車之後要一顆破壞鐵球，模型又畫了一台水泥車，
  在句首寫「這一張不要畫任何車輛」才拉回來。）

---

## 7. 誠實界定：它解決什麼、不解決什麼

| 問題 | 設定圖能解決嗎 | 實際由誰解決 |
|---|---|---|
| **設計一致性**：同一個角色／同一個場景，配色、配件、頭身比例、色溫、光線方向一致 | ✅ **這正是它的用途** | 設定圖 ＋ 引用模板 |
| **指令服從度**：面向、背景透明、構圖 | ❌ 完全沒改善（實測寫了「面向右邊」仍畫成正面偏左、要求透明仍給白底） | 本機後製（三路去背、水平翻轉）＋ 人眼看驗收總覽圖 |
| **幾何一致性**：同組影格的大小、水平位置、腳底高度 | ❌ 解決不了 | **Claude 在遊戲程式端逐張吸收**（見 03 第四節） |

**不要以為加了設定圖就不用管幾何了。**
那組實測落差（同角色不同影格高度差 19.8 個百分點、水平中心飄 8.5pp、底部基準線差 16.6%）
**就是在「有附參考圖、同一個 Project、指令寫得很細」的條件下量到的**。

## 8. 同時維護一份文字版設定表

Sources 裡除了圖，再放一份純文字的設定表，**一個角色／一個場景各一段**。
圖讓模型看得到外觀，文字讓它查得到「這個角色總共要哪些影格、哪些設定已經定案」。

角色：

```
REF001　小師傅
定位：玩家角色，站在鏡頭前方模仿玩家動作
外觀：黃色安全帽（前緣紅色圓徽含「廟」字，兩側青綠雲紋）、白色短袖 T 恤、
      藍色吊帶牛仔褲、紅色領巾、黃橘色工作靴配紅色鞋帶與深咖啡鞋頭、
      約三頭身、腰間工具帶掛鐵鎚、背後斜插一捲圖紙
朝向：正面朝向鏡頭
影格：站立待機／蹲下挖地基／雙手高舉倒水泥／慶祝歡呼
```

場景：

```
REF101　蓋廟工地
分層：天空 → 遠山（偏冷偏淡） → 樹林 → 工地砂土地 → 前景
色調：土黃與草綠為底，主建築的紅金是唯一的高彩度區
光線：太陽在畫面左上，影子往右下
分件：遠山／樹林帶／砂土地面／前景碎石
```

維護規則：

- 名字一律用**遊戲裡的角色名**（小師傅、松鼠小旋風）。**任何真實人名都不要出現**；提到玩家時寫「小玩家」。
- 生完新影格後，如果模型自己加了不錯的新設定（新道具、新配件），**回頭補進這一段**。
  不補的話下次引用時它不會再出現，同一個角色前後就不一致了。

---

## 9. 一個角色（或一個場景）的完整節奏

1. 決定要做哪個角色／場景、需要哪些影格或哪些層 → 先寫進文字設定表。
2. 依第 2 或第 3 節生一張設定圖。
3. **人眼看過**：配色配件清楚、表情討喜、沒有文字。不滿意就重生。
4. 存成 `REF00N.png` / `REF10N.png`，上傳 Sources。
5. 之後每張素材用第 5 節的模板引用；一批 6~8 張放同一個對話連續生。
6. 生完的圖交給本機後製，**方向生反了改設定不重生**。
7. 看一次驗收總覽圖，然後在電視上實際玩過每一關——只截開場畫面會漏掉疊圖與動作接不上的問題。
