## 一、遊戲說明（給玩家的一句話）

你是小小建廟師傅。用身體（或手指）操作 5 種工程車，照 **挖地基 → 倒水泥 → 壓水泥 → 吊建材 → 請神像 → 落成大典** 六個關卡，蓋出一座燕尾脊媽祖廟。蓋好一座，背景聚落就多一間小廟，然後**無限循環**蓋下一座。

**沒有 Game Over、沒有失敗、沒有計時**。唯一的「懲罰」是破壞車開來把東西砸掉（超好笑），而且小孩可以**隨時自己故意召喚它**。

## 三、遊戲流程狀態機

```
menu（開始畫面）
  ↓ 按「用身體玩」→ 開鏡頭 + 載入 MediaPipe（loadingOverlay）
  ↓ 按「用手指玩」→ 直接開始
countdown（3 / 2 / 1 / 開工！　每格 900ms，語音 "Three, two, one, let's build a temple!"）
  ↓
play ── 六階段循環 ──────────────────────────────┐
  ① dig      挖地基                              │
  ② pour     倒水泥                              │
  ③ flatten  壓水泥                              │
  ④ hoist    吊建材（4 件）                       │
  ⑤ install  請神像（3 尊）                       │
  🎉 celebrate 落成大典（7 秒）→ built++ → 背景多一間小廟 ┘
```

### 各階段規則明細

| 階段 | 上場機具 | 完成條件 | 進度條 `state.prog` |
|---|---|---|---|
| ① `dig` | 挖土機 | 挖 **5 下**（`digTarget = 5`） | `digCount / 5` |
| ② `pour` | 水泥車 | 持續倒 **2.5 秒**（`prog += dt*0.4`） | `prog` 本身 |
| ③ `flatten` | 壓路機 | 壓平 **6 個橘色凸起**（碰撞半徑 0.55） | `已壓 / 6` |
| ④ `hoist` | 吊車 | 依序放 **左柱 → 右柱 → 橫樑 → 屋頂** | `(件數 + 對準比例) / 4` |
| ⑤ `install` | 吊車 | 依序放 **千里眼 → 順風耳 → 媽祖** | `(件數 + 對準比例) / 3` |
| 🎉 `celebrate` | — | 固定 **7 秒**，鷹架邊拆邊淡出 | `celebrateT / 7` |

**階段轉場獎勵**：每進入新階段（除了 dig 和 celebrate）觸發 `stepBless()` → 媽祖從天空浮現發光 1.2 秒 + `✨🌟🧧` 噴發 + 煙火 + 鑼聲 + 英文稱讚（"Well done!" / "Mazu blesses you!" 等）。

### ④⑤ 吊放判定（刻意做得非常寬鬆，避免 4 歲挫折）

```
吊鉤 X ← lerp(clamp(kidX, ±2.8), 速度 dt*5)
槽位 X ＝ slot × TS（TS=1.45）→ 實際是 -2.175 / 0 / +2.175
距離 d = |吊鉤X - 槽位X|

d < 0.95 → 累積對準 alignT，**超過 0.3 秒就直接放上去**
d > 1.7  → 累積遠離 farT，**超過 1.7 秒才會招來破壞車**
中間     → 兩者歸零（不罰、不進）
放完鎖 0.5 秒，550ms 後吊下一件
```

> 也就是說：小孩「站對位置一下下」就成功；要「故意停在很遠的地方發呆快 2 秒」才會被砸。破壞車是**獎勵性搞笑事件**，不是懲罰。

## 四、體感偵測（MediaPipe Pose）

模型：`pose_landmarker_lite` float16，`runningMode: 'VIDEO'`, `numPoses: 1`, GPU delegate。畫面**只在裝置上運算，不上傳**。

| 訊號 | 演算法 | 防抖設計 |
|---|---|---|
| 左右位置 `personX` | `1 - (左肩x + 右肩x)/2`（鏡像） | 角色位置再 lerp `dt*6` |
| 肩寬 `shoulderW` | `\|左肩x - 右肩x\|` | 當作距離指標 |
| 雙手高舉 `armsUp` | 兩隻手腕都比肩線高 `shoulderW × 0.5` 以上 | 用肩寬正規化，遠近都成立 |
| 蹲下 `squatting` | `ratio = (腳踝y - 肩y) / 肩寬`；維護一個**自適應站姿基準** `bodyRatioBase`（上升 lerp 0.06、下降 lerp 0.01），`ratio < base × 門檻` 即判定蹲 | **遲滯**：未蹲時門檻 0.80、已蹲時 0.90；一次蹲下只觸發一次（下降緣 `squatEdge`），**冷卻 0.5 秒** |
| 免費破壞車 | `armsUp` **連續維持 1100ms** | 另有 2.5 秒冷卻 |

### 護眼機制（符合全系列鐵則）
- `shoulderW > 0.28` 持續 **400ms** → 判定太靠近
- → 警報音 `sfxAlarm()` + 語音 "Too close! Step back, please!" + **強制暫停 5 秒**（畫面出現紅罩 + 大數字倒數 + 「🛑 太靠近電視囉！往後退～」）
- 恢復時語音 "OK! Let's build!"
- 遲滯：`shoulderW < 0.23` 才解除計時

### 找不到人
超過 2500ms 沒偵測到骨架 → 畫面下方跳出「🧍 站到鏡頭前面吧！」彈跳提示（不暫停遊戲）。

### PiP 小視窗（左下角 160×120）
鏡像的攝影機畫面＋一顆**狀態圓點**：
- 位置：左右＝`personX`
- 高度＋顏色：蹲下 = 74% 咖啡色 `#a86a3a`／舉手 = 20% 粉紅 `#ff66cc`／站立 = 50% 綠 `#00ff88`
- 右上 ✕ 可關閉

**行為（會同步模仿玩家動作）**：
- 位置＝`kidX × 0.7`（clamp ±2.4），加上 `sin(t*3)` 的微幅上下彈跳
- **倒水泥時**手臂舉到 `-2.4 rad`（高舉）
- **挖地基蹲下時**手臂 `+1.0 rad`，而且整個人 **Y 軸壓扁到 0.62**（真的跟著蹲）

### C. 五台工程車（全部 Three.js 積木風）

| 車 | 出場階段 | 構成 | 行為 |
|---|---|---|---|
| 🚜 **挖土機** | ① dig | 黃車身 + 淺藍駕駛艙 + 4 輪 + **可動手臂**（大臂/小臂/鏟斗） | X 跟隨玩家（clamp ±2）；每次挖掘手臂甩到 `-0.9 rad` 再回 `-0.2`（lerp dt*8，動畫 0.35s）；車身固定 `rotY=-0.5` 斜角 |
| 🚛 **水泥車** | ② pour | 綠車身 + 駕駛艙 + 車窗 + **斜置滾筒** + 滑槽 | X 跟隨（clamp -1.5~2.5）；**滾筒持續旋轉** `dt*3`；倒水泥時從滑槽噴出 ⬜ 水泥粒子 |
| 🚧 **壓路機** | ③ flatten | 紅車身 + 駕駛艙 + **大滾筒** + 2 後輪 | X 跟隨（clamp ±2.5）；滾筒**依移動方向正反轉**；碾到凸起、青蛙、小動物都會壓扁 |
| 🏗️ **吊車** | ④⑤ | **刻意只做鋼索 + 吊鉤**（不做塔身，避免擋住廟） | 吊鉤從畫面上方 y=8.4 垂下 4.5，水平 lerp 跟隨玩家；吊件材質 **clone 後半透明 0.72**，才不會遮住廟身 |
| 💥 **破壞車** | 隨時可召喚 | 深灰車身 + 橘窗 + 吊臂 + **擺盪鐵球（鏈+球）** | 從畫面外 -6 開進來（lerp dt*3）；鐵球 `sin(t*6)*0.9` 大幅擺盪；**t>0.9 秒且接近目標時「碰！」**；2.4 秒後開走 |

**破壞車撞擊瞬間會做的事**（`wreckerTick`）：
1. `sfxSmash()` 爆炸音
2. 畫面**震動 14**（相機隨機抖）
3. **整座廟果凍般晃動** `templeWobble = 1`（Z 軸扭 + 上下彈，衰減 1.6/s）
4. 噴出 `🧱💥💨🪨` 16 顆碎片 + `😹🙀` 3 顆
5. **`launchCat()`：一隻貓 🐈 被炸飛上天**（vy=9，帶旋轉，語音 "Meoooow!"）
6. 冒出「碰！」紅色文字
7. 順風耳嚇一跳（`shunShake`）並冒出「？！」
8. 附近的小動物一起被震飛（`smashHold = 0.4` 秒的危險區）

**兩種召喚模式的差別**：
- `summonWrecker()`（放太遠自動觸發）→ 砸掉手上的吊件，重新吊一個
- `freeSmash()`（小孩自己召喚）→ **砸整座廟**：所有已放好的部件全部彈跳一下，但**進度完全不變**（純好玩，不倒退）

### H. 背景聚落（累積成果的視覺化）

每蓋好一座廟，`addVillageTemple(n)` 在背景加一間小廟（石色方塊 + 0.42 倍燕尾屋頂），**左右交錯排列**，越後面越遠（x 每 2 間 +3.2、z 每 2 間 -1.5）。→ 玩越久，背景廟越多，形成一整片聚落。

### I. 發光圈 + 千里眼光束（引導系統）

- **發光圈** `glowRing`：黃色圓環（Torus）平放在目標槽位，透明度 `sin(t*4)` 閃爍、尺寸微幅呼吸、持續自轉
- **千里眼光束** `eyeBeam`：從左上角千里眼助手拉一條**加法混合的青綠色光柱**直指發光圈，透明度閃爍 → 四歲小孩不用讀字也知道要去哪

## 八、已知可改進項目（尚未執行，供未來決策）

1. **語音沒有排隊管理**　`say()` 直接 `speechSynthesis.speak()`，沒有 `cancel()` 舊語音、沒有優先度。熱鬧場面（撞擊+壓扁+驚喜同時發生）會塞車，講出一長串。
   → 全系列後期已建立規範（見記憶「語音實作規範」）：**cancel 舊的 + 加優先度 + rate 1.05 + pitch 隨機起伏**。遊戲7 尚未套用。
2. **`TREASURES` 常數未被使用**（第 730 行宣告後就沒用到了，實際用的是 `SURPRISES`）→ 死碼可刪。
3. **`state.paused` 時 `updateParade` 也停住**，暫停 5 秒期間畫面完全靜止，可考慮讓龍獅繼續動（暫停畫面比較不無聊）。
4. **手指模式沒有「太靠近」保護**（合理，因為是拿在手上），但**手指模式的挖掘沒有連點冷卻**，快速連點可以瞬間挖完 5 下。
5. **`pour` 階段固定 2.5 秒、`dig` 固定 5 下**，沒有隨蓋的座數增加難度。目前是刻意的（零挫折），但可考慮加入「第 3 座之後多一根柱子」之類的微變化。
