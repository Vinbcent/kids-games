超級松鼠小旋風｜遊戲製作計畫

四歲幼兒向的 2D 橫向體感跑酷遊戲。手機開啟 HTML5 遊戲並以鏡頭辨識「跳、蹲、雙手高舉」，畫面再投影到電視；主角會自動向右跑，小朋友用身體動作幫助超級松鼠小旋風前進。

HTML5 Phaser 3 MediaPipe Pose 橫向 16:9 3–6 歲 手機鏡頭體感

1. 核心遊戲概念

跳
小朋友跳起來，角色同步跳過石頭、木樁、倒木。
蹲
小朋友蹲下，角色同步壓低身體，躲過蜜蜂、樹枝、飛鳥。
英雄模式
能量滿後，小朋友雙手高舉約 1 秒，進入英雄模式。

2. 角色與玩法定位

超級松鼠小旋風

唯一主角與遊戲視覺核心。角色自動往右跑，小朋友不是「直接移動角色」，而是透過體感幫助小旋風完成動作。

口頭禪：「衝衝衝！超級松鼠小旋風！跌倒了，就馬上站起來！衝衝衝！」

米多 / 米絲

僅作為輕量配角，主要出現在教學、開場、過關與加油畫面，不在遊戲進行中搶主角焦點。

5. 英雄模式

進入條件

  • 收集 ITEM001 / ITEM002 累積 UI004 能量條。
  • 能量滿時提示小朋友舉雙手。
  • 雙手高舉約 1 秒後啟動。

效果

  • 切換 CHAR011 HeroRun。
  • 搭配 FX001 / FX002 / FX003。
  • 可提高速度或分數，但不建議完全無敵。
  • 時間建議約 8–10 秒。

7. 素材技術規格

角色 / 障礙物 / 收集物 / 特效：以透明 PNG（Alpha）為主；不要把背景、地板或 UI 畫進素材。角色素材盡量維持一致比例、朝右、完整入鏡。

角色素材

  • 建議 1024×1024 原始檔。
  • 透明背景。
  • 角色全身完整。
  • 特效與角色分層。
  • 正式遊戲可再縮圖或整理為 Texture Atlas。

背景素材

  • BG001 使用 16:9 橫向。
  • BG002 水平可重複拼接。
  • BG003 / BG004 作為獨立圖層物件。
  • 可用不同捲動速度形成 Parallax。

9. 體感辨識規則

人體動作遊戲動作建議判定
跳起CHAR004 Jump身體中心 / 髖部相對校正基準明顯上升
蹲下CHAR005 Crouch髖部下降且膝蓋彎曲
雙手高舉CHAR010 → Hero Mode雙手腕高於肩膀並維持約 1 秒

建議判定採寬鬆策略，加入 300–500ms 穩定時間與約 0.8 秒 cooldown，避免幼兒動作不標準導致誤判。

10. 技術架構

前端

  • Vue 3 + TypeScript + Vite
  • Phaser 3
  • MediaPipe Tasks Vision
  • Howler.js（可選）

MVP 運作方式

  • 手機瀏覽器開啟網頁。
  • 使用手機前鏡頭辨識小朋友。
  • 手機畫面直接投影 / Cast 到電視。
  • 第一版不做雙裝置配對。
